# Create Commit Message

変更内容を分析してコミットメッセージを作成するスキル。コミット自体は実行しない。

## 手順

### Step 1: 情報収集

以下の3つのコマンドを**並列で**実行する:

```bash
git status -s
git diff --stat
git log --oneline -10
```

### Step 2: 変更内容の詳細確認

Step 1 の結果から変更ファイルを把握し、`git diff` で具体的な差分を読む。ファイル数が多い場合はカテゴリごとにまとめて確認する。

### Step 3: 変更のグルーピング

変更内容を論理的なグループに分類する。分類の軸:

| カテゴリ | 例 |
|---------|---|
| 機能追加・変更 | 新機能、既存機能の拡張、バグ修正 |
| 開発ツール・設定 | スキル、スクリプト、CI/CD、.gitignore |
| リファクタリング | コード整理、命名変更、構造変更 |
| ドキュメント | README、コメント、スキーマドキュメント |

1つのグループにまとまる場合はコミットメッセージを1つ作成する。複数グループにまたがる場合は、グループごとにコミットメッセージを分けて提案する。

ただし、開発ツール側の変更が機能変更に直接付随するもの（例: 機能追加に必要な設定変更）であれば、無理に分けず1つにまとめてよい。

### Step 4: コミットメッセージの作成

#### フォーマット

`git log --oneline -10` で確認した直近のコミットメッセージのスタイルに合わせる。

1行目はプレフィックス付きの要約:
- `feat:` — 新機能追加
- `fix:` — バグ修正
- `refactor:` — リファクタリング
- `docs:` — ドキュメント
- `chore:` — 開発ツール・設定・依存関係

2行目以降は必要に応じて補足説明を書く。変更の「何を」ではなく「なぜ」を中心に書く。1行目だけで十分伝わる場合は補足不要。

#### 言語

コミットメッセージは日本語で書く（プレフィックスは英語）。

### Step 5: 出力

以下の形式で提示する:

- ステージングするファイルを列挙する場合は、`git add` のコードブロックで提示し、必ず1ファイルにつき1行の `git add <ファイル名>` とする

**コミットが1つの場合:**

````
```
feat: 要約文

補足説明（必要な場合のみ）
```

対象ファイル:
- `path/to/file1` — 変更の概要
- `path/to/file2` — 変更の概要
````

**コミットが複数の場合:**

各コミットに番号を振り、対象ファイルを明示する。コミットする順序も意識して番号を付ける（依存関係がある場合は依存される側を先に）。

````
**コミット1: 短い説明**

```
feat: 要約文

補足説明（必要な場合のみ）
```

対象ファイル:
- `path/to/file1` — 変更の概要

---

**コミット2: 短い説明**

```
refactor: 要約文
```

対象ファイル:
- `path/to/file2` — 変更の概要
````

## 注意事項

- コミットは**絶対に実行しない**。メッセージの提案のみ行う
- `git add` コマンドを提示する場合は、複数ファイルを1行にまとめず、1ファイル1行で列挙する
- ユーザーが「分けてコミットしたい」等と明示した場合は必ず複数に分割する
- ユーザーが特に指示しなくても、論理的に独立した変更群がある場合は分割を提案する
