# Calm Medical Design Guideline

頭痛ノート Web のログイン前ページ、および全体 UI の基準トンマナ。  
モバイルアプリの基準色 `#00A67E` を主役にしつつ、医療サービスらしい信頼感と、毎日使える落ち着きを両立する。

## コンセプト

**Calm Medical**

頭痛や服薬という繊細な情報を、落ち着いて記録・確認できる場所。  
「診療システム」ほど硬くせず、「健康メモ」ほど軽くしすぎない。白、薄いミント、やわらかいクリームを使い、安心感・清潔感・継続しやすさを出す。

## キーワード

- 落ち着いた
- 信頼できる
- 清潔
- やさしい
- 見返しやすい
- 医療っぽすぎない
- 広告っぽすぎない

## 色の使い方

- Primary は画面内で使いすぎない。1画面につき CTA、選択中、重要数値に限定する。
- 背景は白を中心にする。ミント背景はページ全体を少しやわらげる程度に使う。
- `#FFFCF2` はメモ、補足、料金の安心材料など、感情的にやわらげたい場所に使う。
- 赤は削除・エラー・強い注意だけに使う。通常の強調には使わない。
- グラデーションは原則使わない。使う場合はモバイルアプリ由来の `#26A69A -> #26C6DA` を、ヒーローや特別なカードに限定する。

## UI ルール

- 角丸は基本 `8px`、大きなヒーロープレビューやモーダルのみ `12px` まで。
- カードは白背景 + 薄い境界線を基本にする。強い影は使わない。
- 影は浮かせるためではなく、階層を少し分けるために薄く使う。
- 入力欄は高さ `40px` 以上、余白をしっかり取り、焦らせない。
- ボタンは Primary / Secondary / Danger の3系統に整理する。
- 記録カードは「日時」「強度」「場所・症状・対処」を一目で読める密度にする。
- LP のファーストビューには、抽象イラストより実際の記録 UI プレビューを置く。

## タイポグラフィ

- 見出しは太くしすぎず、読みやすさを優先する。
- LP の H1 は大きくしてよいが、アプリ内見出しは控えめにする。
- 説明文は短く、医療広告のような断定表現を避ける。
- 文字間隔は広げすぎない。落ち着いた通常の日本語組みにする。

## 文体

### 目指す文体

- 短い
- やさしい
- 断定しすぎない
- 行動が分かりやすい
- 不安を増やさない

### 例

- 「頭痛の記録を、あとから見返しやすく」
- 「痛みの強さ、薬、対処をまとめて残せます」
- 「今日の状態を記録する」
- 「必要なときに、落ち着いて振り返れます」

### 避ける文体

- 「頭痛を完全に解決」
- 「今すぐ改善」
- 「医師いらず」
- 「あなたの不調を徹底分析」
- 強い煽り、過度な約束、広告的な感嘆符

## ログイン前ページの方向性

ログイン前ページは LP の形を取るが、派手なマーケティングページにはしない。  
ファーストビューで伝えることは次の3つに絞る。

1. 頭痛ノートという名前
2. 頭痛の記録を見返しやすくする価値
3. 実際の記録 UI の雰囲気

推奨構成:

1. ヘッダー: ロゴ、料金、ログイン、主要 CTA
2. ヒーロー: 短い価値提案 + 記録 UI プレビュー
3. できること: 強度、服薬、メモ、振り返り
4. 料金導線: 詳細は料金ページに任せ、ここでは軽く誘導
5. フッター: 最小限のリンク

## 実装時の優先順位

1. CSS 変数としてパレットを定義する
2. Header / Button / Card / Form の共通見た目を整える
3. ログイン前トップページを Calm Medical に寄せる
4. ログ一覧とフォームの可読性を改善する
5. 料金ページを同じトンマナに合わせる
